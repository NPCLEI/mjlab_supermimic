## 一、结论速览

| 结论 | 依据 |

## 二、必须知道的实现细节（踩过的坑）

### 2.1 数据与打包

1. **打包时把数据集自带的 body 数组一起存。**
   引擎的 compact 打包格式只存 `ref`（71 维：根位姿+关节）。此时 `bodies()` 会走**可微 FK** 去现算 14 个 tracked body——纯粹浪费算力。
   本机 `motions_all_sitfiltered` 自带 `body_pos_w/body_quat_w/body_lin_vel_w/body_ang_vel_w`，一起存 fp16 后：22,246 条 / 11,343,510 帧 → **5.74 GB**（打包耗时 **11.6 秒**，NVMe + memmap）。
2. **单条/子集用 npz，全库用 packed `.pt`。**
   22k 条 npz 约 11.6 GB、加载慢；packed 格式 1 个文件、`MotionLibrary(compact=True)` 直接吃。
3. **切片子库时只存需要的字段。** 300 条子集 0.19 GB，评测加载几秒。

### 2.2 训练循环的 10 个真实缺陷（全部实测触发过）

| # | 缺陷 | 症状 | 修法 |
|---|---|---|---|
| 1 | `load()` 在计数器初始化之前 | 续训每段从 it 0 重来、LR 不衰减、ckpt 互相覆盖 | `load()` 放到 `__init__` 最后 |
| 2 | 更新门限用 `buffer.size`（N×rows）| 续训后空缓冲立刻开训 → `no sampleable rows` 崩溃循环 | 用**时间深度** `ptr.min()` |
| 3 | 短 episode 采不出 k 步窗口就直接抛错 | 策略一退化就崩 | 跳过该次更新（记 warning）|
| 4 | **`env.reset()` 双重复位**（env 本身 `auto_reset=True`）| episode 被打断两次、`bin_return` 双更 → 数据污染（it 2700 时 nse1 0.026→0.069）| 适配器声明 `auto_reset`，由它决定谁复位 |
| 5 | **动作未限幅**（采样时）| 解码器无输出非线性，动作可到 **62**，机器人被甩到地上，回报崩到 **−60** | `a.clamp(-1,1)`（mjlab 的 `joint_pos` 期望 ±1）|
| 6 | **动作未限幅**（想象 rollout 里）| 世界模型被推到不可行状态，想象回报 **−537** | `imagine()` 里同样 clamp |
| 7 | **预测四元数未归一化** | `\|q\|` 漂移后 `projected_gravity` 模长错，`upright`/终止判据可被"缩小四元数"骗过 | 用前 `q / \|q\|` |
| 8 | 无信赖域（确定性策略梯度）| 一批坏梯度把策略推飞 → 震荡 | **EMA 行为策略**（τ=0.99）+ 减小逐参数步长 |
| 9 | `imagine` 里硬编码 tracking 的奖励项名/观测布局/噪声维度/历史展平 | 换任务立刻 `KeyError` / shape 错 | 改成 `heads.reward_term_names` / `heads.observation()` / `heads.obs_noise_half` / 单帧恒等 |
| 10 | 诊断调用 `online_error` 未做空窗口保护 | 策略退化到每步终止时抛异常杀死进程（夜间 run 于 it 75750 崩溃）| try/except |

### 2.3 观测/奖励的通用化要点

- **奖励必须在想象里可算**：`r(s,a)` 形式的项才能用；需要接触力/传感器缓冲的项（`air_time`、`foot_slip`、`self_collision`、`soft_landing`、`angular_momentum`）在想象里不存在。
- **论文的 Table A.2 奖励本来就删掉了 self-collision 项**，joint-limit 权重为 −2【社区 `rethinking-supermimic` 明确记录】。所以"去掉接触项"不是妥协，是和论文一致。
- 若某任务的状态奖励与解析实现不一致，策略会精确优化错误目标（实测相关系数仅 **0.557**、均值差 **3.8 倍**、看不见 −0.22/步的接触惩罚 → 必然崩）。

## 三、论文的真实范围与关键陈述

来源：[arXiv:2610.28480](https://arxiv.org/abs/2610.28480)、[项目页](https://supermimic.github.io)（CoRL 2026 Oral）。

### 3.1 任务范围

**只有动作追踪。** 评测集是 BONES-SEED 过滤后的 **129,514 条动作（264.56 h）**，每条从第一帧播放一次，用归一化回报（0..1）+ 失败数衡量；"失败 = 触发训练的终止条件"。
**没有任何速度指令任务，也没有"任意奖励"的实验。**

### 3.2 关键数字

| 项 | 数值 |
|---|---|
| 3 h（1×H100）| 超过 SONIC（7 天 / 128×L40）的回报；**>50× 墙钟、>1000× GPU-hours** |
| 失败动作数 | 3 h：**25** / 129,514；9.8 h（2×H100）：**0**；SONIC 发布权重：179 |
| 世界模型预测误差 | 0.007–0.011（1 h → 264 h 数据都稳定）|
| 想象速度 | 比 MuJoCo Warp 快 **>10×** |
| vs PPO-WM | 达到同等最好回报所需想象步数少 **~64×** |

### 3.3 按动作类别的失败分布（3 h / 9.8 h）

| 类别（条数）| SONIC | 1×H100 3 h | 2×H100 9.8 h |
|---|---|---|---|
| 侧滚 (22) | 全 22 | 2 | 0 |
| 空翻 360/180/90 (44) | 全 44 | 1 | 0 |
| 交叉腿 (10) | 9 | 0 | 0 |
| **躺/休息/起身 (99)** | 28 | **8** | **0** |
| 跳远 (24) | 15 | 0 | 0 |
| 舞蹈 (8) | 全 8 | 0 | 0 |
| 其它 (129,307) | 53 | 14 | 0 |

> **注意"躺/起身"这一行**：与本次实测的 fall/get-up 短板（0.6703、6/6 失败）是同一类。论文证明它随训练量增加会归零 → **短板是数据/算力问题，不是方法缺陷**。

### 3.4 工程超参（论文/项目页明确）

- 想象 **32 步** + **critic 自举**；有 critic 时 **16 步 ≈ 无 critic 的 32 步**；**无 critic 且 ≤16 步会训练失败**。
- 世界模型**每轮都更新**，仅在一次策略更新内部冻结。
- 评测用确定性物理：friction 1.0、无域随机化、无观测噪声。
- 归一化回报 = 未折扣 episode 奖励和 / 上限。

**共性**：全部仍是"参考动作定义目标与奖励"的追踪任务；变化的是**动作类别、仿真器、机器人、网络结构**。未发现速度追踪类复现。

### 4.1 他们的实现里值得抄的做法【社区】

`rethinking-supermimic` 明确列出的选择，其中多条本机引擎**没有**：

1. **每个模块对自己的输入做 running mean/var 归一化**（状态特征、goal、ξ、策略观测、世界模型动作）——本机世界模型**完全没有输入归一化**。
2. 世界模型**输出零初始化**。
3. 世界模型额外预测**逐 body 的接地概率**作为条件。
4. 动力学增量在 **heading 框架**下预测（而非世界系）。
5. `anchor=torso`（默认），根奖励/终止用 pelvis。
6. episode 边界：10 s 或 clip 结束 → **自举而非终止**；想象里用**软 sigmoid** 近似硬阈值。
7. 关节噪声裁剪到软限位 0.9 倍（与 joint-limit 惩罚口径一致）。
8. 观测 = Table A.1 + 6D 参考根朝向 + heading 系根位置误差。

> **这解释了本次速度任务的一个关键现象**：速度任务的状态量级约是 tracking 的 10 倍（关节速度 12 rad/s vs 2 rad/s），而世界模型没有输入归一化 → 学不出 `∂v/∂a`，实测动作敏感度只有真实的 **0.116**。

## 六、硬件与运维经验

1. **A100 必须开 TF32。** A100 的 FP32 峰值只有 **19.5 TFLOPS**，4090 是 **82.6** —— 纯 FP32 下 A100 反而慢 4 倍。设 `TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=1` 后每样本更新成本从 **1.44 ms → 0.61 ms（2.4×）**，这才是能用 2 倍 batch 的原因。满载时 A100 用 25 GB / 80 GB，温度与利用率正常。
2. **长任务用 `systemd-run --user --unit=...`。** tmux/setsid 会随 ssh 会话 cgroup 一起被杀。
3. **显存要按"邻居占用"规划。** 本机 GPU 0 被别人占 10.8 GB，所以速度任务只能用 1024 envs / WM 1024×10；qiyuan 的 A100 空着才能跑论文规模（4096 envs / 2048×10 / 4096）。
4. **评测要素**：确定性物理、无噪声、每条从第一帧播一次、失败 = 触发终止。用同一套脚本比不同配置才有意义。
5. **取最好 ckpt，不要 `ckpt_latest`**（单条任务上差 0.029；全量库上差 0.0033）。
6. **每 30 分钟巡检要看四个量**：`nse1/nse8`、`imag_ret`、`surv`、`train_ret`，以及是否有 `Traceback / OOM / nefc`。单点 benchmark 不足以下结论。
7. **git**：qiyuan 侧 gitea 的 SSH 在 **825** 端口（HTTP 1143），robot 侧已配 `capy-gitea` 别名 + deploy key。

## 七、方法论教训（我这次犯过的错）

1. **不要重写已验证的训练循环。** 四个崩溃型 bug 全部来自为了"通用化"而重写 loop/recorder 语义；源实现的契约（单写入者、`ep_id` 单调、`auto_reset` 所有权）只体现在代码配合里。
2. **对照实验只能变一个变量。** 我最初同时改了 `sampling_mode`、`horizon`、`lr`、`warmup` 并加了分段续训，然后和模板比——方法上无效。
3. **不要从两个点外推上限。** 我曾判断 `body_ori` "上限 0.60"，实际 72%。
4. **`train_ret` 不是能力指标。** 速度任务上 +0.30 是"站着不动"的分数；必须用真实量（`|v−cmd|`、达标率）验证。
5. **警觉"可被利用的物理自由度"**：未归一化四元数、未限幅动作、未裁剪的关节限位惩罚，都会让策略在想象里作弊。
6. **一个假设要被"可测量的量"检验**：把"想象与真实不一致"落到"动作敏感度 0.116"这个数上，才有了明确的修法方向。
7. **对社区证据保持开放**：我一度断言"别的任务做不了"，实际社区已把**动作类别**扩展到空翻/起身/爬行、**仿真器**换到 Isaac Lab/UniLab、**机器人**换到肌肉驱动——正确的说法是"换动作可以，换'无参考动作'的契约不行"。

## 八、下一步（按证据排序）

1. **给世界模型加输入归一化 + 输出零初始化**（对齐社区实现）。速度任务的状态量级是 tracking 的 10 倍，这很可能就是敏感度只有 0.116 的原因。改完复测敏感度：若 →0.5+，速度追踪可以重跑；若仍是 0.1 量级，才是方法边界。
2. **补 fall/get-up 短板**：用 125 条倒地类动作从 0.8248 权重微调 1–2 h（等价论文"3 h → 9.8 h"的增量），目标 6/6 失败 → 0–1。论文同类在 9.8 h 后归零，社区也有专门做 getup 的复现。
3. **稀有类重采样**：倒地类仅占 0.6%（125/22246），按条均匀采样拿不到足够样本；`sampling_mode=return` 只按回报加权，不补偿类别稀缺。
4. **速度任务的备选两条路**：先用 PPO 训会走的策略再灌进回放缓冲（`scripts/seed_buffer.py` 已就绪）；或改奖励地形（`upright` 1.0→0.1、追踪项 5.0）让"站着"不再是局部最优（已验证会开始学，但仍未证明能走出步态）。
## 九、重构落地：`rl_cfg` 与 `env_cfg` 分离（2026-10-29）

### 9.1 契约

新增 `rl/spec.py`（`WmTermSpec` / `RewardCtx` / `SpecReport`）与 `adapters/from_env.py`
（`build_wm_spec(env, cfg)`）。奖励与终止**从 `env.cfg` 反射**，不再有第二份手写实现：

| 通道 | 判定 | 处理 |
|---|---|---|
| `analytic` | 该 term **名字**在 `adapters/terms/registry.py` 注册（tracking 8 项、command 6 项）| 在预测状态上精确计算，与原实现逐位一致 |
| `learned`（默认）| 未注册（需要接触力/传感器）| 每项一个小 MLP，用 **env 自己算的每项数值**（`buffer.r_terms`）监督；`corr ≥ 0.9` 才允许策略使用；输出 `mean±5σ` 限幅；warmup 期预训练 |
| `unavailable` | 既不可解析也不学习 | `strict=True` 时**启动即报错**，否则打印被丢项 |

启动必打印：
```
[wm-spec] analytic 8 | learned 0 | dropped 0 | max_step_reward 0.1000
```

### 9.4 本轮抓到的 4 个真 bug（都是等价性/端到端验证暴露的）

| bug | 症状 | 修法 |
|---|---|---|
| 注册表只按函数对象匹配 | tracking 的 8 项定义在引擎自己的 `supermimic.envs.mdp.rewards`，`getattr(mjlab.mdp, ...)` 全 None → **7 项被误判成 learned**，奖励差 5e-2 | 改为**按 term 名字注册** + 绑定函数对象 |
| `RunningNorm` 被非有限样本污染 | 速度任务摔倒后出现 NaN 状态 → running 均值/方差永久 NaN → 后续 loss 全 NaN（`nse1 nan`）| `nan_to_num` 后再统计，forward 同样sanitise |
| `WmSpec` 未声明 runner 契约标志 | `auto_reset` 默认 False 而 env 也自动复位 → **双重复位**，episode 变 1 步、回报 −4.2 | 从 `env.cfg.auto_reset` 与是否存在 `replay` recorder **推导** `auto_reset` / `writes_buffer` |
| command 类任务未建 heads | 速度任务的 6 个状态项全被判 learned（未训练→≈0）| `_build_heads` 对非 tracking 任务构造 `VelocityHeads` |

### 9.7 哪些奖励项学不到（实测，决定"去掉"的清单）

在 stock 13 项配置上跑约 1600 迭代，learned 头回归环境自己算的每项数值，最终的相关系数：

| 项 | corr | 结论 |
|---|---:|---|
| `angular_momentum` | **0.99–1.00** | 可学 |
| `pose` | 0.84–0.85 | 学不到 0.9 |
| `foot_clearance` | 0.69–0.83 | 学不到 0.9 |
| `soft_landing` | 0.44–0.78 | 学不到 0.9 |
| `foot_slip` | 0.51–0.63 | 学不到 0.9 |
| `foot_swing_height` | 0.38–0.51 | 学不到 0.9 |
| `self_collisions` | 0.22–0.71 | 学不到 0.9 |

`foot_slip` / `foot_swing_height` 本质不能由 `(s, a, ξ)` 唯一决定（取决于接触与相位），`pose` / `foot_clearance`
依赖相位。**结论：这些项从奖励里去掉**，环境与想象同时去掉，保证两边一致——这正是 `-SM` 任务的默认
（`CONTACT_TERMS` 把这 8 项权重置零，剩下 6 个解析可算项）。

闸门行为：learned 项 `corr < min_corr (0.9)` 期间**策略更新被挂起**并打印每项相关性（每 500 迭代一次），
不会拿 0.4 相关的代理去训练。

## 十一、速度追踪：三条路的实测结论

| 路线 | 实测 | 结论 |
|---|---|---|
| 纯 model-based 从零探索（各种调参） | `mean \|v−0.8\| = 0.894`、±0.2 达标 **0.2%**、集长 2.2 s | ❌ 收敛到站着 |
| 改奖励地形（upright 1.0→0.1、追踪项 ×2.5） | 起步更好但机器人立即倒地（`train_ret −3.0`） | ❌ 去掉直立激励就摔 |
| **给示范**：PPO 训 1500 迭代（35 分钟）后测其自身 | `mean \|v−0.8\| = 0.870`、达标 **0.2%** | ❌ PPO 1500 迭代也没学会走；需要更长训练（mjlab 常见 1 万+） |

根因（实测）：**世界模型对动作的敏感度只有真实环境的 0.116**，而站立奖励 `upright` 已经拿满 →
想象与真实环境里"站着"都是局部最优。这不是实现缺陷（奖励已与环境逐项一致、世界模型 `nse1 0.0005`），
而是"无参考动作驱动"任务上的方法前提差异。
## 十二、速度追踪测量方法学与最终数据（可复现）

### 12.1 之前两次测量错在哪

1. **指标错**：用固定的 `cmd = 0.8 m/s` 计算误差，但环境的 twist 指令每 3–8 秒随机重采样（±1 m/s）。
   `|v − 0.8|` 因此没有意义（PPO 拿到 1.44 的跟踪奖励却"误差 1.0"，矛盾即由此暴露）。
   正确做法是对**实际指令**求误差：`|v_xy − cmd_xy|`。
2. **不可复现**：指标修正后仍每次用不同的随机指令序列，同一 ckpt 可测出 8% 或 16%。
   必须固定 `cfg.seed` + `torch.manual_seed`，同一 ckpt 才可比。

### 12.2 固定种子后的曲线（同一指令序列，64 envs × 400 步）

| ckpt | 迭代 | 墙钟 | ±0.2 达标 | ±0.3 | `|v−cmd|` | 集长 |
|---|---:|---:|---:|---:|---:|---:|
| 20000 | 20k | 0.99 h | 8.3% | 14.6% | 0.758 | 2.07 s |
| 40000 | 40k | 1.92 h | 10.3% | 15.0% | 0.754 | 2.65 s |
| 48000 | 48k | 2.30 h | 6.1% | 13.2% | 0.800 | **4.97 s** |

PPO 同墙钟对照：2700 迭代 / 0.9 h → 15.9%；4000 迭代 / 1.3 h → 12.2%。

### 12.3 结论：它在学"平衡"，没在学"跟速度"

集长从 2.07 s 翻倍到 4.97 s（平衡能力显著提升），而速度达标率在 6–10% 之间摆动。
奖励算术上"按指令速度走"约为"站着"的 2.5 倍（0.10 vs 0.04 每步），但**世界模型对动作的响应只有真实环境的
11.6%**，想象里迈步看不出收益 → 策略收敛到 `upright` 已给满分的平衡解。

因此：
- **"速度追踪学不出来"是错的**（能部分跟踪，6–10%）；
- **"给足训练就能走"也没有证据**（2.3 h / 4.8 万迭代后仍停在平衡解）；
- 瓶颈是**世界模型的动作敏感度**，不是奖励一致性、不是实现缺陷（`nse1 0.0009`、`tbce 0.000`、`tacc 1.00`）。
